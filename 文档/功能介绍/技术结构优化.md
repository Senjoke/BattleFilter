# 技术结构优化说明

## 1. 优化背景
随着系统功能的不断增加，原先将所有业务逻辑和数据库查询直接写在 Express 路由 (`routes/`) 中的方式，导致代码耦合度过高，不利于后续维护和测试。此外，针对 C 端用户高频访问的“赛事看板”接口，每次访问都直接查询 PostgreSQL，在并发较高时会造成性能瓶颈。

## 2. 优化内容

### 2.1 Controller + Service 分层重构
我们对后端代码结构进行了标准化的分层重构：
- **`src/controllers/`**：控制器层。负责接收前端发来的 HTTP 请求，进行参数提取和基本校验，随后调用 Service 层的方法，并将结果包装为统一的 `ApiResponse` 格式返回。
- **`src/services/`**：服务层。承载核心的业务逻辑和数据库操作（`pool.query`）。
- **`src/routes/`**：路由层。精简为仅做路由映射和中间件（如 Auth、Tenant 拦截）的绑定。

*注：本次重构保证了核心业务逻辑（如蛇形分队算法、手动编队等）完全不变，仅优化了代码结构。*

### 2.2 引入 Redis 缓存机制
我们通过引入 `ioredis` 客户端，对 C 端的只读高频接口进行了缓存优化：
- **缓存对象**：`/api/board/teams` (队伍列表)、`/api/board/matches` (赛程列表)、`/api/announcements` (系统公告)。
- **缓存策略**：首次请求时从数据库查询并存入 Redis，设置 1 小时的过期时间。
- **缓存失效**：当管理员在后台进行队伍修改、生成赛程、发布公告等写操作时，Service 层会主动调用 `redis.del()` 清除对应租户和周期的缓存，确保 C 端能即时获取最新数据。

## 3. 宝塔服务器部署指南

由于本次优化引入了 Redis，在宝塔面板上部署或升级时，需要进行以下环境配置：

### 3.1 安装与配置 Redis
1. **安装 Redis**：
   - 登录宝塔面板，进入 **软件商店**。
   - 搜索 `Redis`，点击安装（推荐安装 7.x 版本）。
2. **启动与安全配置**：
   - 安装完成后，在软件设置中确认 Redis 服务已启动。
   - 如果您的后端与 Redis 在同一台服务器上，可以保持默认的本地访问；若需远程访问，请在配置文件中修改 `bind` 设置并配置强密码。

### 3.2 环境变量配置
在您的 Node.js 项目根目录（即 `backend/`）下的 `.env` 文件中，增加 Redis 的连接配置：
```env
# Redis 配置 (若无密码且在本地，可保持如下默认设置)
REDIS_URL=redis://localhost:6379
# 若有密码，格式为: redis://:yourpassword@localhost:6379
```

### 3.3 Node.js 项目重启
1. 在宝塔面板的 **网站 -> Node项目** 中找到本系统。
2. 点击 **更新/重新构建**，确保 `package.json` 中的 `ioredis` 依赖被正确安装。
3. 点击 **重启** 项目，使新的代码和环境变量生效。
4. 查看项目日志，如果看到 `Connected to Redis successfully`，即代表缓存模块已正常工作。
