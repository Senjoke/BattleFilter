# 用户行为与系统指标说明

## 1. 业务目标
为了更好地了解本系统的使用情况、统计各社区（租户）的活跃度，我们引入了轻量级的用户行为日志与系统指标模块。该模块可以统计全局和单一租户的累计访问量及每日活跃人数。

## 2. 数据统计来源与技术实现

### 2.1 数据库持久化日志 (PostgreSQL)
- **表结构**：新建了 `access_logs` 表，包含 `id`, `tenant_id`, `path`, `ip`, `user_agent`, `created_at`。
- **触发机制**：通过后端的 `metricsMiddleware`，系统会拦截所有的 C端页面 API 请求（过滤掉了 `/api/admin` 开头的后台管理请求）。
- **目的**：持久化保存每一条访问记录，以便日后进行深度的离线数据分析或安全审计（如防恶意刷接口）。

### 2.2 实时高速指标 (Redis)
由于在关系型数据库中频繁使用 `COUNT` 查询海量日志会造成性能瓶颈，我们利用 Redis 实现了实时指标统计：
- **累计访问量 (Total Visits)**：
  - 每当 C端有有效请求进入时，系统会调用 Redis 的 `INCR` 命令。
  - 分别累加 `stats:total_visits:global`（全站总流量）和 `stats:total_visits:{tenant_id}`（当前社区流量）。
- **每日活跃人数 (Daily Active Users, DAU)**：
  - 使用 Redis 的 `HyperLogLog` 数据结构（通过 `PFADD` 命令）。
  - 根据用户的 IP 地址进行去重估算。
  - 数据键按天划分：`stats:dau:global:2026-05-11` 和 `stats:dau:{tenant_id}:2026-05-11`。
  - *优势*：占用内存极小，在统计海量独立访客（UV）时误差控制在 1% 以下。

## 3. 使用方法与接口

管理员可以通过调用指定的统计接口来获取当前系统的实时指标。

- **接口地址**：`GET /api/admin/metrics`
- **鉴权要求**：需要在 Header 中携带管理员的 `Authorization: Bearer <token>`
- **返回数据结构**：
  ```json
  {
    "success": true,
    "code": 200,
    "message": "获取系统指标成功",
    "data": {
      "globalVisits": 1205,       // 所有租户累计的总访问量
      "tenantVisits": 450,        // 当前租户（由请求头 X-Tenant-Id 决定）的累计访问量
      "globalDau": 89,            // 今日所有租户的独立访客数（全局活跃人数）
      "tenantDau": 42             // 今日当前租户的独立访客数
    }
  }
  ```
- 您可以将此接口的数据直接展示在后台的“数据大盘”或统计模块中。
