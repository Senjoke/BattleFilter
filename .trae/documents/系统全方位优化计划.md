# 系统全方位优化计划 (多租户、数据统计、技术重构)

## 1. 摘要 (Summary)
本项目旨在对 BattleFilter 系统进行全方位的架构升级和功能扩展，具体包含三大核心模块：
1. **技术结构优化**：引入 Controller + Service 标准分层架构，并接入 Redis 缓存高频访问的 C 端接口数据，提升系统性能。通过 Docker 配置和启动 Redis。
2. **多租户架构**：在全链路（前端 `.env` -> 请求头 -> 后端中间件 -> 数据库）打通 `tenant_id`，实现多社区数据的物理隔离，一套后端服务支撑多个前端站点。
3. **用户行为与系统指标**：新增访问日志与数据统计模块，利用 PostgreSQL 和 Redis 统计各租户及全局的累计访问量、流量及活跃人数。

## 2. 现状分析 (Current State Analysis)
- **后端架构**：目前所有业务逻辑、数据库查询均耦合在 `routes/` 目录中，缺乏分层，不利于长期维护和测试。
- **性能与缓存**：完全依赖 PostgreSQL 直接查询，无 Redis 环境。
- **多租户**：系统为单租户设计，无法在一套数据库中安全隔离不同社区的赛事数据。
- **数据统计**：缺乏访问日志，无法得知系统的使用人数、峰值及各社区的活跃度。

## 3. 改造方案 (Proposed Changes)

本计划将严格按照以下三个阶段依次执行，每个阶段完成后输出相应的说明文档至 `e:\BattleFilter\文档\功能介绍\`。

### 阶段一：技术结构优化 (架构重构与 Redis 接入)
1. **Docker 配置 Redis**：修改根目录的 `docker-compose.yml`，增加 Redis 容器配置，并启动该服务。
2. **依赖安装**：在 `backend` 引入 `ioredis` 作为 Redis 客户端。
3. **架构分层重构**：
   - 创建 `backend/src/controllers/`：负责接收请求、参数校验、调用 Service、返回响应。
   - 创建 `backend/src/services/`：封装所有底层业务逻辑和数据库 `pool.query` 操作。
   - 改造 `backend/src/routes/`：精简路由文件，仅负责绑定 URL 与 Controller。
4. **Redis 缓存机制**：
   - 针对 `/api/board/teams`、`/api/board/matches`、`/api/announcements` 等高频只读接口增加 Redis 缓存。
   - 在管理员执行写操作（POST/PUT/DELETE）时主动清除相关 Redis 缓存。
5. **文档输出**：编写 `技术结构优化.md`，详细说明分层逻辑，并提供**宝塔服务器环境下的 Node.js 和 Redis 部署配置指南**。

### 阶段二：多租户架构 (Multi-Tenant)
1. **数据库改造**：
   - 更新 `database/schema/00_ultimate_init.sql`，为核心表增加 `tenant_id VARCHAR(50) DEFAULT 'default' NOT NULL`。
   - 更新相关表的 `UNIQUE` 约束（如 `UNIQUE(battle_tag, period_id, tenant_id)`）。
   - 新增 `database/schema/04_upgrade_multi_tenant_and_logs.sql` 平滑升级脚本。
2. **后端租户识别**：
   - 增加租户中间件 `tenantMiddleware`，从请求头读取 `X-Tenant-Id`，注入到 `req.tenantId`。
   - 改造所有 Service 层的 SQL 查询，必须带上 `tenant_id = $x` 条件。
3. **前端多租户注入**：
   - 在前端根目录的 `.env` 中增加 `VITE_TENANT_ID=default`。
   - 在 `frontend/src/api/request.ts` 中拦截器加上 `config.headers['X-Tenant-Id'] = import.meta.env.VITE_TENANT_ID`。
4. **文档输出**：编写 `多租户架构说明.md`。

### 阶段三：用户行为与系统指标 (Log & Metrics)
1. **持久化访问日志**：
   - 在数据库新建 `access_logs` 表。
2. **实时指标统计 (基于 Redis)**：
   - 累计访问量：使用 Redis 统计 `stats:total_visits:global` 和 `stats:total_visits:{tenant_id}`。
   - 活跃人数统计：使用 Redis `HyperLogLog` 估算 DAU 和在线峰值。
3. **后端 API 与中间件**：
   - 增加 `metricsMiddleware` 拦截并记录 C 端用户的访问。
   - 提供 `/api/admin/metrics` 接口供查看统计数据。
4. **文档输出**：编写 `用户行为与系统指标.md`。

## 4. 假设与前置条件 (Assumptions & Decisions)
- **Redis 环境**：将使用 Docker 启动 Redis。
- **重构原则**：重构仅改变代码组织结构，绝对不改变上一版本中已实现的业务逻辑。
- **数据库升级**：将同时提供“全新初始化”和“平滑升级”两套 SQL 方案。

## 5. 验收标准 (Verification Steps)
1. **Docker 验证**：Redis 容器成功启动并能在 Node 中连接。
2. **重构与 Redis 验证**：后端服务正常启动；缓存命中与失效逻辑工作正常。
3. **多租户验证**：前端修改 `VITE_TENANT_ID` 后刷新，互相不串库。
4. **指标统计验证**：在 Redis 缓存或数据库中看到访问量增加，正确区分全局和单一租户。
5. **文档检查**：`e:\BattleFilter\文档\功能介绍` 目录下生成了三个详尽的 Markdown 说明文档。
