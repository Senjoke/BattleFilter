# 守望先锋赛事分队算法优化计划

## 1. 摘要 (Summary)
本项目旨在优化 BattleFilter 的分队管理系统，重点改进**自动分队**与**手动分队**算法。
自动分队将引入“基于群号隔离”以及“基于段位分数均衡（蛇形分组）”的逻辑，确保对战组内的玩家来源一致且实力相近；同时保留原有的 1-2-2 职责强制槽位，不足时允许空缺。
手动分队将解除职责与群号的硬性绑定，仅保留队伍 5 人上限，并增加“队伍内手动调整玩家职责”的功能，以提供更大的灵活性。

## 2. 现状分析 (Current State Analysis)
- **自动分队 (`/group/:groupId/autofill`)**：
  - 当前采取纯贪心算法，仅为了凑齐 1重装 2输出 2支援 的职责。
  - 缺乏群号 (`wechat_group`) 过滤，不同群的玩家会被混编。
  - `score` 目前在代码中被硬编码为 0，完全没有读取玩家报名时的自填段位（`self_ranks`）进行实力均衡。
- **手动分队 (`tryAddPlayerToTeam`)**：
  - 目前在前端严格校验玩家的意向职责与队伍空缺槽位，如果不匹配则直接拦截，无法实现跨职责的强制编队。
  - 无法在队伍编成后手动修改玩家的具体职责定位。

## 3. 改造方案 (Proposed Changes)

### 3.1 自动分队优化 (Auto-allocation)

**核心逻辑改进**：
1. **交互变更**：
   - 管理员在前端点击“自动填充本组”时，弹出一个选择框，让管理员选择目标“微信群号”（下拉列表根据当前未分配池的玩家群号动态生成）。
2. **段位分数转换算法 (Rank Calculation)**：
   - 新增一个通用工具类/函数，用于将 `self_ranks` (如 "黄金1", "白银5") 转换为数值分数。
   - **转换规则**：
     - 大段位基础分：青铜=1000, 白银=1500, 黄金=2000, 白金=2500, 钻石=3000, 大师=3500, 宗师=4000, 英杰=4500。
     - 小分段计算：每个段位包含 5 个小分段（5最低，1最高）。计算公式：`基础分 + (5 - 小段位) * 100`。例如“黄金1” = 2000 + (5-1)*100 = 2400。
   - **实力计算模式**：
     - 主要采用**职责法**：当玩家被分配到特定位置时，使用其对应位置的段位分。如果某位置未定级，则退化使用其所有已定级位置的**平均分**。
     - *预留扩展接口*：设计一个 `ScoreModifier` 接口，为未来接入第三方战绩（真实胜率、核心指标）预留计算加权的位置。
3. **蛇形均衡分配算法 (Snake Draft Balancing)**：
   - 过滤出指定群号的未分配玩家。
   - 按照预设的槽位需求（重装 2，输出 4，支援 4），分别从过滤后的池子中筛选出具备相应职责意向的玩家。
   - 对每个职责池内的玩家，按照其“职责分数”从高到低排序。
   - 采用蛇形分组（Snake Draft）将玩家交替分配到 Team A 和 Team B：
     - 重装 (2人)：1st -> A, 2nd -> B。
     - 输出 (4人)：1st -> A, 2nd -> B, 3rd -> B, 4th -> A。
     - 支援 (4人)：1st -> A, 2nd -> B, 3rd -> B, 4th -> A。
   - 如果某个职责的候选玩家不足，则分配完现有玩家后，剩余槽位留空。

**涉及文件**：
- `frontend/src/views/AdminView.vue` (修改弹窗交互，传递 `wechatGroup` 参数)。
- `backend/src/routes/teams.ts` (接收 `wechatGroup`，提取 `self_ranks`，引入实力转换与蛇形分组算法)。

### 3.2 手动分队优化 (Manual allocation)

**核心逻辑改进**：
1. **解除硬性限制**：
   - 修改前端 `tryAddPlayerToTeam` 函数，移除对 `assignedRole` 的严格空缺检测和群号检测。
   - 仅保留 `team.members.length < 5` 的上限拦截。
   - 强制加入时，如果玩家有首选职责且队伍该职责有空缺则分配该职责，否则默认分配一个占位符职责（如“补位”或随便选一个该玩家会的职责），允许管理员后续修改。
2. **队伍内职责调整**：
   - 在前端队伍成员列表中，为每个成员增加一个“职责下拉框”或“编辑职责”按钮。
   - 允许管理员随时将队伍内的某玩家职责从“输出”改为“支援”（即便该玩家报名时没有选支援）。
   - 调整后触发 `/admin/teams/edit` 接口更新持久化数据。

**涉及文件**：
- `frontend/src/views/AdminView.vue` (重写手动添加逻辑，增加职责调整 UI 组件)。
- `backend/src/routes/teams.ts` (后端 `/edit` 接口已有更新能力，主要确保接收并覆盖新的 `assignedRole`)。

### 3.3 附加优化建议 (Additional Optimizations)
1. **战力可视化展示**：在前端队伍面板的标题旁，动态显示当前队伍的“综合平均实力分”，以便管理员直观判断两支队伍是否均衡。
2. **缺位明显标识**：当自动分配因为人数不足导致留空时，队伍 UI 中显式渲染出“缺少 1 名输出”的空槽位占位符，方便管理员有针对性地进行手动补人。

## 4. 假设与前置条件 (Assumptions & Decisions)
- **假设**：所有段位字符串都符合“大段位+数字1-5”的格式（如“黄金1”），如果无法解析则给予默认保底分（如1500）。
- **决策**：手动分队的越权操作完全由前端放开拦截，因为后端 `/edit` 接口本身只负责接收最终的 `members` JSON 数组并持久化，不进行复杂的业务规则校验。

## 5. 验收标准 (Verification Steps)
1. **自动分队测试**：
   - 点击“自动填充”应弹出群号选择框。
   - 填充后，Team A 和 Team B 的所有成员必须来自选定的同一个群号。
   - 成员按实力均衡分布在两队，两队相同位置的玩家分数差尽可能小。
   - 如果对应位置玩家不足，队伍人数应少于 5 人，不会拿其他位置的玩家硬凑。
2. **手动分队测试**：
   - 可以将任何玩家加入到任何未满 5 人的队伍中，无视群号和职责冲突。
   - 可以在队伍列表中直接修改某位玩家的职责（例如把只会玩输出的玩家强制改为重装），并成功保存。
3. **数据验证**：刷新页面后，上述自动和手动的编队结果（包括强制修改的职责）均能正确从数据库恢复展示。
